## 1. 本次范围

第一阶段只为本机明确指定的一个已有受管原生会话增加 Telegram 输入与有限回复，限定一个使用者及其私聊。Telegram 端会话列表、切换、新建、恢复、群聊和多用户仍不在此阶段。

当前运行基线是 [ADR 0039](decisions/0039-cc-viewer-style-runtime.md) 的普通原版 CLI、PTY、模型代理和异步观察。旧 Session Kernel、App Server 控制入口和持久 command/CAS 不是现行能力，也不作为 V3 强制前置。新增渠道应先验证输入、来源归属和必要交互，再选择最小后端变更。

## 2. 源码核对

下表只说明当前代码可以证明什么。拥有接口或通过 V2 测试，不等于已经完成 Telegram 验收。

| 用户结果 | 当前可复用能力 | V3 缺口与限制 |
| --- | --- | --- |
| 指定已有受管会话 | [Application](../src/workbench/application.rs) 的 `RunSummary` 和 Run 注册有运行 ID、状态及可用时的原生 Thread ID | Run 与 Thread 不是同一身份；原生 `/new`、fork 或退出可能改变目标。须明确绑定身份和失效规则，不能仅按 cwd、PID 或“当前会话”选择 |
| 交给原生 CLI 输入 | [TerminalHandle](../src/workbench/terminal.rs) 的 `input` 与 [InputControl](../src/workbench/control.rs) 提供单 actor、generation、连续 sequence 和失效检查 | 这是字节写入。没有语义消息提交确认；草稿、picker、审批和追问状态下不能盲目粘贴并 Enter。部分写入或 ACK 丢失不能自动重发 |
| 观察真实提交身份 | [请求 metadata](../src/workbench/decode/request.rs) 可提取 Thread/Turn；[原生 UserMessage parser](../src/workbench/rollout/parse.rs) 可读取 Thread/Turn/item 身份；[LiveHub](../src/workbench/live.rs) 按身份合并 | metadata 可缺失或冲突，且两种证据均没有 Telegram task 来源。相同正文、时间临近或“最近输入”不足以证明渠道归属 |
| 回传指定任务回复 | `LiveHub::subscribe` 有运行 epoch、阅读 sequence、有界队列和重订阅要求；模型内容有 request/response/item 身份 | 订阅覆盖整个 Run。须新增可靠 task → 原生提交/Turn → 回复关联及出口过滤；不能直接转发整个订阅或历史快照 |
| 确认整轮结束 | [安装版 CLI 测试辅助](../src/workbench/proxy/tests/native_cli/resume.rs) 读取原生 `task_complete` / `turn_complete` 作测试证据 | [生产 rollout reader](../src/workbench/rollout.rs) 主要处理用户、命令和 patch 记录，尚无渠道所需的完整 Turn 终态投影。模型 `response.completed` 不能替代原生 Turn 完成 |
| 处理审批和追问 | 官方 TUI 的原生交互仍可使用，已有 [V2 支持边界](codex-native-cli-workbench-support.md) | 没有已交付的 Telegram 语义请求、响应、过期检查或来源路由。模型工具参数和 ANSI 文本都不能充当可响应的原生请求 |
| 慢渠道不阻塞原生运行 | [Capture](../src/workbench/capture.rs)、LiveHub、异步 Recorder 已将观察与转发分开 | 新渠道发送和持久化仍须在观察侧隔离；缺口、淘汰或身份冲突后，不能继续把内容当作已归属回复 |

这些缺口需要局部设计和验证；不据此预设 App Server、协议 relay、named profile 限制或整体重构为必选。

## 3. 第一阶段用户流程草案

下列流程用于形成详细设计和验收用例，未确定的交互支持与并发规则不在本文冒充已确认决定。

1. 使用者在本机选择已有受管会话，看到准确目标，明确开启 Telegram 输入与指定任务回复。
2. 本机完成使用者及私聊绑定。未匹配身份、未完成绑定和失效绑定均不能提交或读取内容。
3. 渠道区分“消息已接收”和“原生提交已确认”。只有得到可靠提交证据后才能显示后者；结果未知时保留不确定状态。
4. 已确认的渠道任务沿用指定会话上下文，只将可以证明属于该任务的允许回复发回绑定私聊。本机任务和来源不明内容不外发。
5. 必要交互按逐类支持矩阵处理。安全响应必须关联具体原生请求；未支持的交互清楚说明处理入口，保留原生权限，不默许、不跳过。允许哪些交互回本机处理仍须明确。
6. 本机撤销、运行退出或绑定目标身份变化后使旧授权失效；旧消息和旧按钮不能操作后续会话。是否需要重新绑定必须在详细设计中说明。

输入和发送的状态分别表达：渠道接收、提交确认/不确定、等待交互、任务完成/失败/不确定，以及回复发送确认/未送达/不确定。任务完成不等于回复送达。

## 4. 实现前必须解决的契约

| 契约 | 需要证明或明确的内容 |
| --- | --- |
| 绑定目标 | 使用哪些 Run epoch 和原生会话身份；身份未就绪、Thread 切换、CLI 退出、重启和本机撤销如何失效 |
| 输入确认与去重 | 渠道消息身份、原生提交证据、重复投递处理；各写入边界失败如何区分未提交与结果未知，禁止不确定输入盲目重放 |
| 输入并发 | 本机有草稿、CLI 忙碌、处于交互或输入权被接管时的行为；同 Turn steer 是否允许及如何归属。拒绝或排队仍是待定选项 |
| 来源证明 | 如何将渠道 task 与实际原生 UserMessage、Turn、模型回复可靠关联；缺失、冲突、子代理和迟到事件如何处理 |
| 完成与外发 | 原生整轮终态的可信证据；回复类型与范围；观察缺口、取消及发送结果未知如何报告，不外发历史、reasoning、完整工具输出、cwd 或 diff |
| 必要交互 | 哪些审批/追问/其他请求可远程响应、哪些需要本机；请求身份、重复/过期响应、撤销和失效校验 |

V3 目标已经确认，因此可以继续设计与隔离验证。实现会扩展 ADR 0039 的原生唯一输入/审批入口；具体语义输入机制、远程授权、安全边界、协议耦合和去重/恢复的数据模型须在实现前形成对应 ADR。保留原版 CLI、不自动升级、loopback 默认及旧 `/v1` 只读约束继续适用。

## 5. 最小实施顺序与通过条件

### 5.1 先验证来源与原生交互边界

使用已有测试设施，在独立 HOME/USERPROFILE/CODEX_HOME、合成模型和合成渠道中验证一次外部输入能否可靠关联原生提交及 Turn，并与本机输入区分。此片不连接真实 bot，不读取私人会话，不改变生产默认入口。

必须覆盖同正文、交错输入、原生草稿、审批/追问、模型多次调用、迟到 rollout、观察缺口及写入后 ACK 丢失。通过条件是能说明每个确认的依据，或给出明确失败证据。若当前 PTY 路径无法证明这些关系，记录失败和替代方案，再决定最小变更；不能以文本/ANSI 猜测补齐成功。

### 5.2 打通一条受控渠道任务

在完成对应契约和 ADR 后，实施一个已有会话、一个绑定私聊、一条纯文本消息、可靠原生提交关联、一条允许回复和明确错误路径。身份校验、去重、来源过滤、异步发送及本机撤销必须随此闭环交付，不留为后续安全补丁。

通过条件包括上下文继续生效、本机输入不外发、整轮与发送状态准确、无自动重放不确定输入，以及慢渠道/存储不阻塞原生运行。合成 Bot API 测试不能替代真实 Telegram 验收；真实试用须按具体支持范围单列证据。

### 5.3 补齐必要交互与恢复

按照明确支持矩阵实现审批、追问、取消及降级；覆盖重复/过期操作、授权撤销、CLI 退出、重启、网络失败和发送结果未知。完整第一阶段必须通过下节适用用例；单条文本闭环不是完整交互交付。

跨会话管理继续按 V3 计划第二阶段单独设计，不因本片增加会话列表、切换或新建能力。

## 6. 首阶段验收矩阵

| 场景 | 通过条件 |
| --- | --- |
| 正常对话与已有上下文 | 输入进入准确的已有会话；多模型/工具调用不提前结束；可信整轮证据后才报告任务完成 |
| 本机与渠道来源隔离 | 相同文本、连续/交错输入、steer、子代理与迟到事件不会混发；缺失或冲突来源时停止自动外发 |
| 原生输入状态 | 草稿、Slash/picker、审批、追问、忙碌和接管期间不把普通消息当作操作答案；控制字符、多行、超长和未支持媒体有明确规则 |
| 重复与不确定提交 | 重复渠道消息不重复执行；写入前失败、部分写入、ACK 丢失、证据延迟和崩溃不盲目重试 |
| 完成证据 | `response.completed` 后仍有工具/模型调用时任务不提前完成；有可信证据则报告取消/退出，半行、缺口或无法证明任务结局时标记不确定 |
| 必要交互 | 允许/拒绝/取消和追问答案只作用于准确请求；陈旧、重复、另一任务或撤销后的操作失效；不自动审批 |
| 授权与绑定失效 | 错误 user/chat、群聊及伪造操作不能读写；转发消息不据转发来源授予权限；目标替换/退出不会自动跟随；撤销或目标变化后，已入队未发送的正文/交互仍须重验绑定版本，不能沿用旧授权外发 |
| 慢渠道与恢复 | 慢发送、限流、断网、满盘和队列满时 CLI 继续、有界内存、明确降级；发送结果未知不宣称 exactly-once |
| 内容与凭证 | 只回传允许的已归属内容；token、HTTP 凭证、私人正文不进诊断/fixture/Git；不自动镜像终端和历史 |
| V2 回归 | 原生权限、模型转发、网页、异步保存、设备隔离和旧 `/v1` 只读仍保持原行为 |
