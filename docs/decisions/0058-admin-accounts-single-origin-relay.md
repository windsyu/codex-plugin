# ADR 0058：管理员账号与单端口可信工作台前端

- Status: Accepted
- Date: 2026-10-13

2026-10-14 补充：[ADR 0061](0061-account-deletion-admin-rename.md) 将默认登录名改为 `windsyu`，增加普通账号删除与 schema 3 无损迁移；下述 `admin` 默认名称保留为原决定背景，不是当前登录名。

## Context

用户确认不开放自行注册，由默认 `admin` 创建用户；手机登录后访问同账号所有电脑。服务器安全组只允许使用现有选定的一个 HTTPS 入口，不能以端口池或 wildcard DNS 作为新模式前提。[ADR 0056](0056-public-workbench-relay.md) 的邀请注册和独立工作台 origin 不能满足该流程；[ADR 0057](0057-single-workbench-ip-trial.md) 的双端口单电脑仅保留为显式兼容配置。

## Decision

1. 使用私有密码文件幂等初始化 `admin`，无公开默认密码。同名普通账号报冲突，不自动提权。管理员创建普通账号、设临时密码、重置、禁用/恢复；账号管理不授予他人电脑的访问权。临时密码登录后仅允许账号信息、改密和退出。
2. SQLite schema 2 引入角色、强制改密及认证代际。改密、重置和禁用在同一事务中增加账号代际并删除网页会话及兑换材料，使旧批准结果和电脑凭据不再有效；随后关闭连接。尚未批准的设备码仍需使用当前有效会话批准。批准、登录、重连在各自受理点再次检查当前代际及状态。恢复账号不能恢复旧凭据。
3. `--single-origin` 通过 `/g/{gatewayId}/` 提供中转构建的前端；API/SSE/WS 验证页面授权后剥离前缀，进入已有 RemoteOwner。页面授权绑定原门户会话、账号代际、电脑和 UI/API 版本；每次请求同时要求原门户 Cookie。ID 是非独立授权的 selector，不能仅凭 Cookie 和路径自动创建新授权。旧标签不会借用之后登录的身份。
4. 共享 `codex-workbench-assets` crate 仅嵌入可信静态资源，不依赖本机 CLI 模块。HTML/JS/CSS 由中转提供；电脑响应仅允许路由确定的 JSON/SSE/终端帧。中转控制 MIME、CSP、nosniff、缓存与引用策略，剥离 Cookie、重定向及资源加载头。工作台 API 兼容号首版严格匹配，版本不符提示升级，不回退加载电脑脚本。
5. 设备码授权变为“登录并开启”；私有凭据成功落盘后才连接。原登记恢复需要旧独立电脑凭据证明和原所属账号重新批准；UUID 本身不是凭证。不采集硬件指纹，不保存密码，不影响本地 CLI。

## Alternatives

- 独立子域提供真正的浏览器 origin 隔离，但不能满足当前仅 IP 的约束；保留为显式配置和独立测试路径。
- 每电脑分配端口增加安全组入口，且同 IP Cookie 不按端口隔离，拒绝用于新模式。
- 直接按路径代理电脑 HTML/JS 会让任一电脑代码获得门户同源权限，拒绝。
- 仅依赖当前登录 Cookie 会使旧页面在账号切换后继承新身份，拒绝；必须固定页面授权。

## Consequences

路径不是浏览器隔离边界。虽然电脑不能提供可执行网页，同源可信前端一旦出现 XSS，攻击者仍可能影响当前账号的所有工作台。必须继续执行 Markdown 清洗、文本文件展示、API 白名单和终端安全渲染；不能声称不同电脑在浏览器中实现强隔离。管理员/中转运营者仍属可信方，首版不提供端到端加密、项目共享、只读角色或 V3 IM。

schema 1 升级事务保留 UUID、密码哈希、电脑归属；旧用户默认普通账号，旧会话/邀请/凭据失效。升级前备份，电脑与中转需配套升级，原登记重新认证后恢复。发生撤销、改密或删除后禁止恢复陈旧数据库复活权限；按 [ADR 0061](0061-account-deletion-admin-rename.md)和[部署指南](../guides/public-relay-deployment.md)保留当前数据并选择兼容二进制或前向修复。单端口与域名模式不隐式混用。真实手机/TLS/恢复演练不由合成测试替代，支持边界见[支持文档](../codex-native-cli-workbench-support.md)。
