# ADR 0065：以 main 为基础整合历史模块与公网中转 API 2

- Status: Accepted
- Date: 2026-10-15

## Context

用户要求 `codex/public-relay` 建立在 main 基础上，并恢复本机和远端已有历史。分叉后的中转分支只识别 catalog v2，main 的历史模块已使用 v4；共用数据根时，旧程序明确拒绝读取未来版本，历史接口返回 `cache_version_unsupported`。main 同时增加会话分组和用户归类，不能只修改版本常量。

## Decision

合并 main 的完整历史实现、API、前端、测试及契约，保留中转分支提交，使 main 成为中转分支祖先。保留独立页面、目录浏览、后台服务、固定远程授权和实例隔离状态。分叉期间重复使用的历史呈现 ADR 0056 在整合树中编号为 0064，原中转 ADR 0056 保持。

工作台 UI/API 升至 2，传输 VERSION 2、relay schema 3、JSON 配置 schema 2 均不变。中央前端、relay 和电脑端必须严格匹配；旧页面从门户重新打开，不借用新 Cookie 补发旧授权。精确放行会话分组 GET 与归类 GET/PUT，所有处理器使用既有 Application owner/RemoteOwner 验证，配对设备不获得全局历史权限。中转外层边界继续拒绝重复 `If-Match`；允许转发的业务头保留全部值，使电脑端能拒绝重复 `Content-Type`，无法表示的允许头值直接拒绝。

现有 catalog v4 沿用主线读取逻辑，不删除、不降级、不手工改版本。原生历史与工作台日志保持原位，正常索引更新仍可写派生缓存；独立用户归类状态不是可丢弃缓存。

## Alternatives

- Cherry-pick 整个主线提交：功能可带入，但无法表达 main 是祖先的分支关系。
- Rebase 中转提交到 main：可以满足祖先关系，但重写既有提交；本次选择保留历史的合并。
- 只调索引版本或重建旧索引：遗漏分组、呈现与归类契约，且旧新程序切换仍会重现问题。
- 保持 API 1：新 UI 会误接入缺少分组接口的旧电脑；需要额外能力协商，本次采用既有严格版本门禁。

## Consequences

两组件须配套构建和部署；已有账号及电脑注册不需要重建，旧工作台页面授权需要重新打开。合成测试覆盖现有 v4 缓存及归类保留、RemoteOwner 正向读取/写入、配对/跨账号/撤销与请求前置条件负向行为。实际部署、Chrome 和私有数据的验证范围单独记录，不把正常运行声明为只读检查。
