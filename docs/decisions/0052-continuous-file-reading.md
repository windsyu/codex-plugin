# ADR 0052：连续滚动的只读文件阅读

- Status：Accepted
- Date：2026-09-22

## Context

用户试用 302 行文件时反馈，“上一段／下一段”不符合 IDE 的文件阅读习惯。后端已经返回完整、有界的文件正文，分页只是前端每 200 行的展示限制。直接把所有行渲染成 DOM 会随行数增长；自行虚拟化还需要正确处理跨屏选区、复制、键盘导航、查找和超长行。

参考事实：[VS Code 文本缓冲设计](https://code.visualstudio.com/blogs/2018/03/23/text-buffer-reimplementation)说明逐行对象可能使内存远大于原始文件；[CodeMirror 官方视图实现](https://github.com/codemirror/view/blob/main/src/editorview.ts)提供文档模型与可见区域渲染分离，[官方只读示例](https://github.com/codemirror/website/blob/main/site/examples/readonly/readonly.ts)保留可聚焦阅读与只读属性。本项目采用其交互与资源管理思路，不宣称采用 VS Code 的 piece tree 实现或相同性能。

## Decision

使用 CodeMirror 6 的 state/view/commands/search 构建只读阅读区。引擎按需动态加载，当前文件与 Git 内容 Diff 都是一个连续滚动文档。保留行号、行号跳转、横向滚动、选区复制和文件内查找（按钮或 Ctrl/⌘ F）；Diff 使用增加/删除/块标题颜色，并保留对应源行的可键盘操作按钮。搜索返回内容作为纯文本，无 HTML/Markdown 执行。

资源边界：

- 继续沿用后端文件、Git 输出最多 1 MiB 的预算；超限明确拒绝，二进制和路径访问规则不变。
- 仅维护中央当前文档，无多标签文档缓存；CodeMirror 只绘制视口附近的行，并处理超长行的可见区域。文件不再按 200 行分页，也不按 4000 字符截断长行。
- 使用库的文本模型；不额外为每行创建含完整文本的业务对象。Diff 额外保存一个 `Int32Array` 源行映射，每行 4 字节；装饰仅对可见区域计算。
- 同 revision 的轮询只更新读取时间，不重建文本模型或选区。内容变化时只替换公共前后缀之间的差异，映射选区和滚动位置；内容已经删除时位置只能收缩到仍存在的文本，不承诺保持原来行号的语义。
- 切换文件/模式/中央页或关闭时销毁阅读实例；动态加载完成前关闭时不创建迟到实例。保留现有可见查询的轮询与取消规则。
- 原始响应、模型和更新期间的临时字符串都受单文件预算约束，但 1 MiB 是文件大小上限，不是整个浏览器的内存承诺；用真实 Chrome 测量多行极端文件及关闭后堆占用。

浏览器仍无文件保存、Git 写操作或命令执行接口。组件只读，同时禁用 contenteditable；只读区可聚焦以支持复制与导航，不主动抢终端焦点。没有新增用户配置、目录、API、migration、语法语言包或编辑器插件。

## Alternatives

- 全量 DOM：实现短，但极多短行会产生大量节点，影响网页及终端响应。
- 自行滚动窗口：体积小，但必须自行实现虚拟 DOM 下的跨屏选区与全文复制/查找，维护成本高。
- Monaco：更接近 VS Code 的完整编辑器内核，本轮仅需要只读阅读，暂不引入完整编辑器及语言服务的装配。
- 服务端分块/按需读取超大文件：需要新的行索引、版本一致性与随机读取接口；本轮不扩大 1 MiB 的已验证边界，后续有实际超大文件需求时独立设计。

## Consequences

新增四项直接依赖及锁定的传递依赖，代码许可证沿用各包 MIT。阅读引擎独立打包，不进入初始工作台主 JS；首次打开文件需要加载该资源，失败可重试。界面保留目录列表、Git 记录的原有分页，仅移除文件正文分页。

ADR 0050 的读取/安全约束继续有效，其前端 200 行/4000 字符限制由本决定替代。实现位置：`FileReading.tsx`、`FileDocument.tsx`、`fileView.ts`。验证见[连续阅读记录](../validation/native-cli-continuous-files-2026-09-22.md)，实施状态只在[计划](../v2-implementation-plan.md)维护。
