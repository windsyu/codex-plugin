# ADR 0055：项目会话的分层展示与本机可撤销归属

- Status：Accepted（A–D 实现、独立复核与逐项验证完成；实测范围及保留限制见验证报告，未部署或整理真实历史）
- Date：2026-10-08

## Context

R6-F.1 已将展示项目与 recordedCwd 分开，并修复已知 Desktop 日期目录、旧库 NULL 与父关系。当前首页仍默认同级展示主/子代理和三类来源记录；选中项目标题依赖当前页，搜索、来源和主子过滤同时影响项目导航。用户希望继续借鉴 token-monitor 的优点，解决会话按项目分组不明确与杂乱数据，并明确不关注 worktree。

token-monitor 提供“路径身份、元数据补全、明确来源的辅助会话折叠”参考，但它的项目统计按目录名合并，且部分分类依赖私有 SQLite；这两项不满足本项目的身份与兼容边界。已有原生/Observer 显式关系可以支撑有限的来源折叠，不能证明 Workbench Run 与某一个 thread 是同一会话。

## Decision

实现采用以下方案，详见[项目会话整理契约](../codex-native-cli-workbench-session-organization.md)，支持限制见[支持文档](../codex-native-cli-workbench-support.md)：

1. 保留完整路径项目身份和既有自动归属。项目导航独立于会话搜索/来源/类别，选中项目摘要不依赖分页。未归类记录说明证据原因，不将不确定性伪装成无项目。
2. 展示分为主要会话、明确辅助会话、工作台运行记录；unknown 默认可见。有可信同 nativeHome/thread 且有效项目/类型一致的来源可以折叠成展示组，每个成员保留正文、Token、coverage 和能力；组不是新可恢复会话。
3. 类型判断只来自已验证元数据，token-monitor 的 guardian 规则不能直接迁入。没有受测 rollout/公共协议事实时保留已知子代理/unknown；不读取原生私有 SQLite。
4. 给 owner 单条记录的显式项目覆盖、未归类和恢复自动规则；不自动跟随父/子/其他来源。覆盖是展示偏好，不改变 recordedCwd、源身份、恢复、运行互斥、文件根或设备授权。
5. 覆盖是不可派生的用户状态，存于有效 dataDir 的 `organization/state.sqlite`，自有 schema 1；与可重建 `library/catalog.sqlite` 分开。统一 JSON 配置不增加第二份副本，原始来源不迁移。事务内 CAS、store_id + 单调修订及每次查询核验共享状态，保证不同 config 共享 dataDir 时不依赖进程内锁。首次意图在私有 pending 库 FULL 事务提交后不覆盖发布并同步目录；失败孤儿保留诊断，不成为正式空库；ACK 前获取当前提交快照。自己的经身份/权限核验状态库允许无 CREATE 读写连接做 hot-journal恢复，随后query_only；catalog及原始来源仍只读。
6. 新组查询/单条覆盖接口仅 Application owner 使用，复用 Origin、instanceId、来源撤销、强引用 If-Match 和修订校验。目录游标绑定 catalog、规则、覆盖和查询；正文窗口游标只绑定源修订以保留锚点。状态故障明确不可用，不误用自动或旧覆盖，独立来源正文/原cwd恢复可降级继续；新项目启动不绕过校验。
7. 不做 Git/worktree、按名字/正文猜归属、跨路径自动合并、批量整理或删除。每项变更均需验证读写隔离、冲突处理与可撤销行为。

本决定采用新整理视图和单条本机覆盖；R6 §14 的归属/只读/恢复安全规则仍适用。原“无人工归类配置”是 F.1 当时范围，不阻止本次新增独立状态存储和owner写入口，不修改历史只读来源的语义。

## Alternatives

- 只改文案或给所有会话加标签：可作为第一片，但不能消除默认混列、来源副本和意图不明的少量误归属。
- 按 basename 合并，或推导 Git/worktree 根：可能合并不相关项目，且用户明确不关注 worktree。
- 自动读正文/标题进行主题分类：缺少可验证项目身份，会扩大敏感内容处理和模型调用范围。
- 将无项目、空内容、子代理或过期记录删除/默认不可达：把整理变成清理，会丢掉可读证据和合法未知记录。
- 把覆盖存在可重建 catalog：索引重建或缓存维护会丢失用户意图。
- 把所有覆盖塞进 config.json：当前配置上限 64 KiB，不适合增长的逐记录状态，也会让一般设置保存与整理高耦合。
- 以多个来源拼成一个完整正文/Token 会话：无法证明覆盖连续性，Workbench Run 还可能跨多个 thread。

## Consequences

新增用户整理状态的备份/回退边界和 owner 写接口，需 migration 幂等、crash、CAS、失效身份与负向权限测试；catalog 的类型投影需独立版本重建，不能误删状态库。缺失、损坏或未知状态版本不能统一当成“没有覆盖”。

默认 UI 和计数语义改变，需明确展示组与来源记录的区别，并兼容旧直达/筛选链接。来源仍可完整核查，整理不扩大手机授权或改变 `/v1`。新目录不自动迁移或删除任何原始数据；旧 binary 可读原来源但不使用覆盖，回退不承诺相同整理视图。

逐片实现保持来源只读和原cwd恢复，完整标准检查、系统Chrome、release新查询、状态故障/CAS、三来源零写与官方CLI公开no-daemon专项已通过。默认daemon、双OS进程压力与物理故障等未测边界不因本ADR接受而扩大支持；用户试用、部署与远端Git操作仍需分别明确执行。
