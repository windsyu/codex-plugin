# ADR 0046：用户用量概览与折叠诊断

- Status：Accepted
- Date：2026-09-20

## Context

R3 试用中，用户指出左下角和展开面板主要是保存序号、运行 ID 等开发数据，要求改为模型 Token 等实际使用统计。既有用量仅在单次请求详情中展示，响应列表会淘汰；直接在浏览器累加列表会在重连或淘汰后变化，也可能重复计数。

## Decision

1. 底栏优先显示本次运行的已知 Token、输入、输出、缓存命中和简短保存状态。展开面板显示累计已知总量、输入/输出/缓存/推理明细、统计覆盖和保存提示；技术信息放入默认折叠的“诊断详情”。
2. 统计范围为本次启动后的已观察模型响应，含对话与辅助请求。它不是原生 Thread 的终身用量、账户配额、上下文窗口占用或计费账单。切换历史时底栏仍明确属于当前运行。
3. 在观察层独立维护按 `(requestId, responseId)` 去重的有界用量表。缓存/推理明细不再叠加到总量；总量缺失而输入、输出均合法时才以两者之和补出。缺失保留未知、实际零保留零；非法或冲突报告从合计排除，单次响应详情继续保留诊断证据。
4. 统计不依赖可淘汰的正文/响应预览，不逐帧 GET，不查询磁盘。快照和响应/诊断事件携带整体 `usageSummary`；浏览器替换整体摘要，不自行累加事件。Recorder 异步保存同一摘要，旧历史缺字段仍可读，新运行从零开始。
5. 最多保留 16,384 个响应身份，达到上限后明确提示后续新响应未计入，仍保留既有身份以防迟到重复计数。内部宽整数求和，超过 JavaScript 安全整数时不返回失真数字。观察缺口、未识别响应与未上报用量分别保留范围信息。
6. 保存失败和历史缺失继续常驻简短提示；详细保存水位、进程/运行身份与解析日志按需展开。用户操作统计面板不发送终端输入、不改变当前 CLI。

## Alternatives

- 仅替换标签或累计当前页面上的响应：无法保证刷新、重放、缓存淘汰后的统计稳定。
- 继续把全部诊断默认展开：不符合用户确认的界面优先级。
- 从 CLI 屏幕解析用量，或加入价格、账户额度、上下文占用估算：当前没有可靠数据依据，也不属于本次范围。
- 保存全部响应正文以维持总量：占用不必要内存，统计只需要身份和数值。

## Consequences

新增可选的安全数值摘要字段，不更改原生输入、模型路由、旧 `/v1`、旧数据或存储格式版本。合计表示已知用量而非完整账单；冲突被排除时数值可能向下修正，必须同时提示。旧单次用量入口保留，响应观察时长仍不汇总为任务耗时。

本次属于 R3 用户试用改进，实施与验收只在[实施计划](../v2-implementation-plan.md)维护。
