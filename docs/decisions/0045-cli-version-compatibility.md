# ADR 0045：CLI 版本提示与启动准入分离

- Status：Accepted
- Date：2026-09-20

## Context

用户将官方 Codex CLI 从 `0.154.0` 升级到 `0.155.1` 后，正式工作台因版本字符串不相等直接退出。该检查把本项目的受测基线当成兼容性结论，尚未执行实际接入就拒绝启动。用户明确要求正常 CLI 升级不应使工作台立即不可用。

## Decision

1. 删除精确版本准入，不另设最低版本、major 范围或绕过参数。继续使用用户自行安装的原版 CLI，不下载、升级、降级或改写它。
2. 保留有界 `--version` 探测，确认命令成功、输出可识别；失败、超时、超限与非法输出分别报安全错误，不回显原始输出。允许 release、prerelease 与 build 标识，具体约束见[详细设计 §2.1](../codex-native-cli-workbench-detailed-design.md#21-入口与生命周期)。
3. 已回归版本仅作诊断元数据。未回归版本打印一次提示后继续，列表更新不决定运行权限。启动 ready JSON 增加 `cliVersion`，便于问题诊断。
4. 实际 provider/profile、upstream、认证、配置来源与传输检查继续保留，错误说明对应原因。版本号不同不等于这些检查失败；能启动也不等于所有未来协议已验证。
5. 新版本改变观察结构时沿用既有安全诊断和不完整性语义，不猜消息角色、关联身份或执行成功；观察降级不应因版本号直接阻断原始合法流量。

## Alternatives

- 继续精确锁定：每次用户升级都需要工作台发布，即使交互没有改变，已被用户否定。
- 设置“允许未知版本”开关或只放宽 patch 版本：仍让常规升级依赖额外操作，版本范围本身不能证明实际不兼容。
- 删除全部探测和配置检查：会失去错误可执行文件与真实路由问题的诊断，本次没有必要扩大范围。

## Consequences

用户升级后可以直接尝试运行；未测版本可能有尚未发现的参数或观察格式变化，须针对实际失败处理，不承诺全部未来版本兼容。回归使用安装版 `0.155.1`、临时 home、合成模型与本机 Chrome，覆盖正式启动、对话、审批/追问、重连、resume 和历史。另用未来版本 fixture 证明无需增加版本白名单。

此次不改变模型路由支持范围，不涉及数据 migration、全局配置、旧 `/v1` 或旧服务切换。属于 R3 试用修复；[验收证据](../validation/native-cli-version-compatibility-2026-09-20.md)与阶段状态分别在验证报告和[唯一实施计划](../v2-implementation-plan.md)维护。
