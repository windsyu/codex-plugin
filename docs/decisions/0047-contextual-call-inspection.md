# ADR 0047：将模型请求页面收拢为调用详情

- Status：Accepted
- Date：2026-09-20

## Context

用户认可 Token 用量概览后指出，“模型请求”与实时对话高度重复。原页面再次显示模型正文和工具卡，额外的实际请求上下文、参数与逐次用量却位于折叠区域。直接删除全部请求阅读会丢失辅助请求、未归属 WS 内容、原生子命令与调用诊断。

## Decision

1. 移除独立“模型请求”页面及顶栏“网络”、活动栏和侧栏入口。实时对话继续展示用户、模型与工具，模型回复与工具卡均提供“调用详情”。
2. 调用详情在中央阅读区域内打开侧面板，复用现有按需读取、分页、手动刷新与安全预览。调用列表从“用量概览 → 查看调用记录”进入，仅显示模型、用途、逐响应 Token、状态与观察时长；列表不额外请求详情。
3. 保留辅助、未知及诊断请求。普通对话正文不在详情复制；没有进入聊天的正文/工具在详情中折叠展示，支持未归属 WS 的中间态阅读。原生命令、文件修改及工具上下文保持按现有证据关联。
4. 同一请求或 WS 连接中的各响应分别显示用量与时长，不根据 create 到达次序猜配响应，也不累加为任务耗时。缓存淘汰后累计用量仍保留，列表明确说明其预览范围。
5. 历史对话使用相同详情组件及独立调用列表入口，绑定历史 epoch/before；底栏始终打开当前运行的调用记录，关闭后保留原阅读选择。
6. 关闭/换请求释放详情和在途读取；普通流式更新保留已读内容、展开与焦点。面板内 Escape 关闭并恢复入口焦点，被覆盖的阅读区域临时 inert。原生终端始终保持同一节点、进程及输入目标，其 Escape 不被拦截。

## Alternatives

- 继续保留独立页面但改名：重复正文与入口仍存在，没有解决日常使用的干扰。
- 删除所有请求阅读：会丢失实际上下文、逐次统计以及无法归入聊天的调用记录。
- 在每条消息内直接铺开请求全文：长上下文干扰对话阅读，还会增加渲染与获取负担。

## Consequences

仅改变前端导航、阅读布局与相应测试；不更改模型采集、代理/PTY 转发、API、存储格式、累计用量计算或原生 CLI 配置，无 migration。详情仍是有界脱敏副本，缺失、省略、截断和淘汰不会被隐藏。早期静态原型及历史验收截图保留为当时记录，当前约定以[方案 §1.6](../codex-native-cli-workbench.md#16-对话内调用详情与用量中的调用记录)为准。

本次属于 R3 用户试用改进，状态与验收只在[实施计划](../v2-implementation-plan.md)维护，不提前进入 R4。
