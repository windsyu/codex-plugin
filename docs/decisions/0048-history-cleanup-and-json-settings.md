# ADR 0048：显式历史清理与统一 JSON 工作台配置

- Status：Accepted（设计决定；实现状态仅见实施计划）
- Date：2026-09-20

默认路径部分由 [ADR 0049](0049-workbench-user-directory.md) 更新为用户主目录下 `.codex-web/config` 与 `.codex-web/history`；下文保留原决定，配置/清理契约继续适用。

## Context

用户要求显示历史占用、按运行删除、批量清理和可选保留期限，默认不开启删除；长期用户配置应集中到指定目录的 JSON，并由简单网页表单修改。R3 完成时按项目/运行保存独立阅读副本，仅提供历史读取；本决定通过 R3.1 增加清理与配置管理。原生 Codex 设置仍由 CLI 管理，不能把新增入口变成任意文件或原生命令写接口。

现有 `meta.json` v1 严格拒绝未知字段且没有 endedAt；以文件 mtime 或 startedAt 计算“结束后保留天数”会误删旧/长运行。另有多个 launcher 共用数据根和配置目录，需要活动锁、并发写入及故障恢复边界。

## Decision

1. 默认 `$CODEX_HOME/workbench/config/config.json`，以 `--config-dir` 选目录；默认数据根继续为 `$CODEX_HOME/workbench-data-v1`，不迁移旧数据。JSON 分为 launch、storage、history，带 schemaVersion；长期用户设置统一纳入同一契约，网页读写同一文件，CLI 显式参数仅覆盖本次。
2. 手动删除总开关和自动保留开关默认 false；保留天数初值 90，只有两个开关都开启才自动清理。策略在同一配置目录下共享，但每个工作台仅处理绑定数据根和当前 canonical cwd 项目，服务关闭时不安排系统后台任务。
3. 配置和网页共享校验、默认值及修订冲突处理；固定私有目录内原子写入，保留一份有效旧稿，拒绝未知版本/字段。运行中配置失效时暂停删除并保留当前 CLI。启动/路径修改下次启动生效，不自动搬迁历史或重启进程。网页采用当前工作台按钮点击展开的轻量表单面板，收起保留未保存草稿，不新增独立设置页面、导航项或前端路由，不切换中央阅读或终端。
4. 占用在独立有界工作线程扫描普通文件逻辑字节数，明确测量时间、partial 和未知；暂存未删除数据单列。不给出无法保证的物理空间释放承诺，模型/PTY/Recorder 不等待扫描或清理。
5. 按 Run 删除，单次和批量共用冻结候选预览、一次确认、后台任务与逐项结果。当前 Run 永不删除；其他目标必须身份/项目匹配并可取得独占运行锁。预览后重新检查配置、元数据与目录身份，拒绝跨项目、symlink 和路径替换。
6. 任务先持久化删除意图，再原子移至同数据根的私有暂存目录，后台删完整运行，失败/重启可继续。它不是回收站；配置关闭时不续删，取消只作用于尚未开始的运行。派生索引和历史游标随删除失效，结果记录不含会话正文。
7. 自动保留只处理正常结束、非活动且有有效 `lifecycle.json` 的 Run。该独立版本化凭证绑定最终已同步 meta 摘要/序号，保存结束时间；不改 meta v1，不为旧/异常记录编造时间。凭证缺失或损坏只跳过自动清理，已停止且身份可信的旧记录仍可手动删除。
8. 新设置与清理 API 仅位于 `/workbench/v1`，沿用配对、严格 Origin/Host/CSRF 和当前 runEpoch 校验。此决定扩展 R3 的只读历史管理边界；历史正文仍只读，旧 `/v1`、原生会话/认证/模型/权限和旧 Observer 数据保持不变。

## Alternatives

- 开箱自动按天/容量删除：违背默认关闭删除的要求，且现有旧记录缺少可靠结束时间。
- 只提供 Shell 删除说明：用户难以核对运行范围、活动 writer 和磁盘占用，无法完成网页管理闭环。
- 浏览器 localStorage 与配置文件分别保存：容易漂移，不能让手动编辑与网页得到同一设置。
- 直接在 meta v1 加 endedAt 或用 mtime 替代：前者破坏严格旧读者，后者不能证明结束时间。
- 立即递归删除任意目录或仅清掉 SQLite：无法安全校验目标或恢复中断，索引删除也不释放历史正文。
- 同时增加归档、回收站、跨项目清理和容量淘汰：扩大首片状态与删除范围，当前需求可用按运行清理实现。

## Consequences

增加独立配置写接口和历史删除能力，需要对应的负向/崩溃/并发验收。旧记录自动保留更保守，UI 必须显示跳过原因；暂存失败的内容仍占空间。结束凭证是新增旁路文件，无原生/旧数据库 migration，兼容性必须用既有读者 fixture 核实。共享 JSON 不提供项目覆盖层；任意外部编辑器不遵守工作台锁时仍有竞态，不能承诺完美文件 CAS。
