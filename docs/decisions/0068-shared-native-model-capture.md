# ADR 0068：统一模型捕获与原生配置职责

## Status

Accepted。统一接入及本机真实 ChatGPT 捕获已验证；实现、构建与安装验收分别记录在受管产物中。

## Date

2026-10-29

## Context

ADR 0067 为避免 View 拒绝原生合法配置，将默认 OpenAI 和非 `custom` provider 分到无模型捕获的原生直连。它解决启动兼容，却使正常 CLI 对话不再进入实时阅读、调用详情和用量记录。用户明确要求恢复原设计，并指出配置合法性应由官方 CLI 负责，不能把 View 自己的 provider/认证白名单当作原生配置契约。

现有 Capture、Observer、decoder、LiveHub 和 Recorder 并不依赖 provider 名称。限制位于启动接入适配器；它同时承担了配置门禁、路由读取和已知秘密收集。共同协议管线可以复用，但反向代理仍需在覆写本次进程地址前取得正确的原始上游。

本地 CLI 0.165.0 的真实 ChatGPT 专项还发现：终端已得到回复时，观察侧报告不支持压缩，页面未形成请求和响应。未协商压缩的合成服务不能覆盖这个差异；共用捕获管线需要补齐原生传输适配，不能仅删除启动门禁就宣称验收完成。

后续协议诊断确认本机请求使用 HTTP Zstd，模型端点的 HTTP 200 响应省略 Content-Type。官方 0.165.0 [请求实现](https://github.com/openai/codex/blob/360319d8dee62d87e2d59fc0c21805d79519cfed/codex-rs/codex-api/src/endpoint/responses.rs)支持压缩请求，[响应实现](https://github.com/openai/codex/blob/360319d8dee62d87e2d59fc0c21805d79519cfed/codex-rs/codex-api/src/sse/responses.rs#L543)直接解析 SSE 字节，不要求响应声明媒体类型。View 原有的两项观察假设比官方 CLI 更窄。

## Decision

1. 配置合法性、默认值、认证方式、命令凭据执行、刷新、模型和权限由官方 CLI 持有。View 不要求 provider 命名为 `custom`，不以未知字段、可省略字段或认证形状决定 CLI 是否可以启动。
2. 接入层只读取本次转发所需的有效路由、对应的地址覆写字段和脱敏材料。内建 OpenAI 使用原生 `openai_base_url`；其他 provider 使用其 `model_providers.<id>.base_url`。保留 provider、认证和原生传输选择，所有接入复用已有观察、实时阅读和异步保存管线。
   使用已安装原版 CLI 的短命 stdio 辅助进程读取官方 `config/read`、requirements 和必要的 `account/read`，不创建 thread、turn 或模型请求；真正对话仍由独立普通 TUI 持有。它只用于取得原生有效配置和账户路由，不恢复旧外部 App Server 对话控制架构。
3. 读取路由与校验配置分离。代理自身仍校验转发目标、loopback 能力、来源一致性和资源边界；不得将未知原始目的地猜成固定 OpenAI/ChatGPT 地址，也不得将未选 provider 的表当作有效路由。原生有效配置和运行时账户路由的来源必须有实际证据。
4. 原生配置读取或路由解析失败不代替 CLI 报 TOML/认证错误。CLI 保留原始启动和诊断；捕获不能接入时明确报告具体接入原因与不完整状态。该降级不能算作恢复完整捕获的验收通过。
5. 转发不记录认证头；已知秘密收集只为脱敏，不成为认证许可检查。命令 token 的执行与缓存继续只归 CLI。观察或保存失败不得反压模型转发，也不得触发自动请求重放。
   原生 ChatGPT 路由依据官方账户结果绑定 origin、账户和地区覆盖字段；不能把独立的显式上游改成 ChatGPT。源配置与认证版本变化须在转发前重新确认或使本次接入失效，不能仅凭相同账户 ID 将新凭据发向旧路由。
6. 本轮不引入 TLS 解密代理、系统 CA、官方 CLI 补丁、外部对话控制内核或传输降级。不改 `/v1`、Relay wire、用户历史格式和真实原生配置。
7. SSE 与原生默认 WebSocket lane 共用正文、详情、工具和用量模型。WS 请求、响应和原生 thread/turn 的关联须依据实际 `response.create`、响应生命周期和元数据；预热不能变成用户对话，不使用“连接上最后一个请求”代替身份。没有归属证据、流缺口或并发歧义时保留未知状态。
8. 压缩只在观察副本内按实际编码与协商参数解码，解压输出、上下文和缓存均须有界。原始转发字节不经过解压再压缩，不关闭 CLI 的压缩或 WebSocket。未知扩展、损坏输入、资源超限和观察缺口仍标记不完整；已确认的官方辅助通知不应被误当作响应生命周期破坏。
9. 对明确的模型 `/responses` JSON POST、请求声明 SSE、成功 HTTP 200 且响应未声明媒体类型的组合，观察侧采用 SSE 解码提示，以兼容实测原生行为。该提示不改转发的响应头；未知端点、错误响应或显式其他媒体类型不据此猜成 SSE。

## Alternatives

- 继续以 provider 名称分配捕获能力：将项目限制误当成协议差异，不能满足用户要求。
- 仅删除校验而不核对原始上游：可能使 CLI 启动成功却转发到错误目标，不采用。
- 先改成新的 TLS 观察架构：当前共同捕获管线尚可复用，不作为本轮前提。
- 只增量阅读 rollout：可补工具执行和历史，但不能替代流式正文和逐调用详情。

## Consequences

View 的职责收敛为原生启动、明确路由接入和观察，不维护第二套 CLI 配置合法性规则。验收须分别覆盖普通 provider、原生 OpenAI、实际认证选择、SSE/WS、多轮、工具、调用详情、用量、保存和恢复。默认原生账户路由还须证明目的地保持正确；合成固定上游的成功不能冒充真实 ChatGPT 验收。

旧无捕获状态和历史 reader 保持兼容；恢复捕获只影响新 Run，不补造旧记录中未捕获的正文。源码方案、专项结果和本地安装状态分别报告，不由文档决定宣称未执行的测试通过。
