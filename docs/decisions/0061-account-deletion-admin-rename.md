# ADR 0061：中转账号删除与默认管理员无损改名

- Status: Accepted
- Date: 2026-10-14

## Context

用户要求账号管理提供删除功能，并将默认管理员登录名从 `admin` 改为 `windsyu`。现有中转已保存管理员密码、UUID、电脑归属和有效会话，不能以重新初始化账号实现改名。[ADR 0058](0058-admin-accounts-single-origin-relay.md) 的管理员角色与账号隔离仍适用，本决定覆盖默认登录名及补充删除契约。

## Decision

1. 默认登录名为 `windsyu`，权限仍以 `role=admin` 判断，不以用户名判断。私有密码文件初始化和停服恢复均使用此名称；正常重启不重置密码。`windsyu` 不可用于创建普通账号，`admin` 可作为普通用户名，不能因名称获得权限。
2. SQLite schema 3 在一个事务中，将 schema ≤2 的 `role=admin AND username=admin` 改为 `windsyu`。保留 UUID、密码哈希、状态、认证代际、电脑归属和凭据；已有有效登录不因改名失效。目标名称占用时明确报冲突并回滚，不覆盖、合并或提权普通账号。schema 1 的既有授权撤销迁移保持不变；旧二进制拒绝打开 schema 3。
3. `DELETE /relay/v1/admin/users/{id}` 返回 204。事务受理时重新验证有效管理员会话；禁止删除自身或任何管理员，只允许普通账号。失效身份返回 401，受保护目标返回 403，不存在目标返回 404。精确 Origin、请求大小和并发限制不变。
4. 同一事务删除目标账号、电脑登记、网页/页面会话及一次性交换材料；保留仅含 UUID/固定事件的审计。提交后关闭失效隧道和业务流。登录、密码哈希完成、绑定批准、兑换、重连及 HTTP/SSE/WS 最终受理点重查数据库，删除后不能复活旧权限。同名重建获得新 UUID，不能继承原电脑或旧凭据。
5. 门户删除前明确确认不可撤销、撤销全部中转登录及删除电脑登记。取消不发送 mutation，失败不隐藏账号，迟到结果不借用新身份。删除不修改电脑原生 Codex 历史，也不停止已运行的本机 CLI。

## Alternatives

- 将禁用当删除：仍保留账号和登记，无法满足永久移除要求。
- 新建 `windsyu` 并删除 `admin`：丢失 UUID/电脑归属且可能重置凭据，拒绝。
- 每次启动重命名：可能误迁移之后创建的同名普通账号；以 schema 事务标记一次性迁移。
- 升级失败自动恢复旧数据库：可能复活已删除账号、旧密码或撤销凭据，拒绝。

## Consequences

升级前必须一致性备份、核查名称冲突、验证迁移和配套分发许可。schema 3 不能进行旧版的 binary-only 回退；迁移后健康检查失败须停服并保全当前数据，不能自动恢复旧快照。人工恢复必须先核对备份后账号删除、改密及禁用等变更，再撤销恢复库会话/电脑授权；仅提升认证代际不能防止旧密码或已删除账号重新登录。无法安全核对时保持停服并请求决定。详见[部署指南](../guides/public-relay-deployment.md)。

管理员的登录页和门户显示 `windsyu`；旧电脑私有凭据缓存的用户名仅是展示标签，不作为认证或归属依据，下一次重新认证更新标签。无工作台 API/传输版本变化，不强制重启本机 CLI。真实账号删除不作为部署冒烟测试；验证使用隔离合成账号。
