# main 历史模块与公网中转整合验证（2026-10-16）

## 范围与依据

用户要求 `codex/public-relay` 建立在 main 基础上，恢复本机与远端已有历史，并更新原有中转部署。整合前中转分支为 `1c522fb`，本地 main 为 `d3057c2`，已获取的 origin/main 为 `5c4ba29`。采用 merge 保留中转提交，不 cherry-pick 整个功能或重写共享历史；先整合 main 历史，再带入 origin/main 的工作区 FD、脱敏性能及录制器测试修复。决策见 [ADR 0065](../decisions/0065-main-history-relay-integration.md)。

旧程序只支持 catalog 2，而本机已有 catalog 4，导致历史接口返回 `cache_version_unsupported`。原数据存在且 SQLite 检查正常，故整合完整新版 reader、分组、呈现与归类能力，不删除原始历史、派生索引或独立归类库，不手工改版本。

## 实现与边界

- 工作台 UI/API 升至 2；传输仍为 2、中转 schema 仍为 3、JSON 配置仍为 2。已有账号和电脑登记沿用，旧 API1 页面需从电脑门户重新打开。
- 会话分组和归类路由使用 Application owner/有效 RemoteOwner 验证；配对设备不获得全局历史权限。保留跨账号、跨电脑、撤销和来源授权检查。
- 新路由仅精确放行；中转保留允许业务头的所有值，重复 If-Match 在中转返回 403，重复 Content-Type 由本机返回 415，拒绝请求不会改变归类或 ETag。有效归类 PUT 与读回通过，原生文件字节不变。
- 浏览器历史状态继续按账号、电脑和实例隔离；后台服务、目录浏览、独立页面和原终端流程保留。
- Chrome 揭示短折叠窗口滚动会卸载仍可见的记录。滚动选择现保留可见已挂载块，详情期间固定来源窗口，关闭后在 layout 阶段恢复焦点且不隐式滚动。另以失败回归证明迟到的旧位置响应会淘汰当前窗口，改用当前窗口 ref 淘汰。仍限制三块/48 条挂载、五块缓存，不宣称填满多个短折叠块的整个视口。
