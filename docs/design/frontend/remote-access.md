# 前端远程连接设计

[前端设计](README.md) · [布局与实现映射](workbench-ui.md) · [中转交互契约](../../interactions/relay.md)

远程连接是已经实现的产品能力，工作台的新导航必须保留它。远程功能补齐后，由 Open Design 重新组织商业版布局。原图和独立原型导出属于本地资料，由 Git 忽略；本文维护远程功能的入口、身份差异与状态表达。

原型使用合成电脑、账号、地址和二维码，只模拟界面状态；生产功能仍由现有后端、门户与终端协议提供。本次不新增认证方式、远程权限或 API。

## 1. 入口与信息层级

| 位置 | 设计 |
| --- | --- |
| 顶部产品导航 | 工作台、可访问的“我的电脑”、连接管理；本机门户链接仅来自有效 HTTPS 中转根地址，远程返回同源门户 |
| 电脑身份 | 顶栏和侧栏底部持续显示电脑及本机/远程/仅当前运行范围；远程显示名称只按固定 gatewayId 查找，失败时使用明确的短 ID，不猜电脑名 |
| 侧栏“远程连接” | 仅本机 owner 显示电脑公网连接器状态与管理入口 |
| 连接管理 | 正常页面中的本机公网接入；当前 Run 局域网管理保留独立地址。商业原型把两类信息并列，但不合并生产生命周期 |
| 配对浏览器 | 只显示当前 Run 的可用功能，不显示全局电脑列表、共享设置或接入管理 |
| 异常与底栏 | 连接、输入不确定性、响应结束及保存状态各自保留原有证据和提示，不用一个“在线”掩盖其他状态 |

“远程连接”是工作台内的发现入口。公网管理属于 Application，本地局域网管理属于当前 Run；页面布局不合并它们的授权或生命周期。

## 2. 本机公网接入

本机 owner 填写 HTTPS 中转站根地址与电脑名称，点击“登录并开启公网接入”。绑定卡显示示例设备码、期限、验证入口和取消操作。用户在账号门户登录，核对电脑名称、设备码与完整工作台权限，明确批准后才进入连接中和在线状态。

| 状态 | 展示与操作 |
| --- | --- |
| 未绑定 | 中转站地址、电脑名称和登录按钮 |
| 等待账号确认 | 设备码、约剩余期限、显式验证入口、取消登录 |
| 已连接 | 中转站、电脑名称、账号；关闭接入与退出登录分开 |
| 已关闭 | 保留绑定信息，允许重新开启 |
| 离线等待重连 | 表达网络不可用；本机 CLI 继续运行 |
| 登录失效 | 重新登录并由原账号批准，不能以重试网络代替认证 |
| 绑定失败/过期 | 明确未成功接入，可重新发起 |
| 服务器撤销未确认 | 本机已断开，提醒到门户删除登记，不声称双端撤销完成 |
| 私有状态保存失败 | 提醒关闭状态未保存、重启前处理，不能声称旧凭据已清除 |

取消或关闭会结束本次绑定意图。旧批准结果不能满足后来发起的新绑定，也不能让已经关闭的连接重新开启。关闭接入保留登录；正常退出登录撤销本机登录及门户登记；门户主动撤销则使电脑需要重新认证。新批准成功后恢复有效登记。

绑定批准文案明确包含原生终端、文件、历史、项目启动与设置，不画成只读观察权限。中转登录与官方 CLI 的模型认证继续分开。

实现对应：[RelayPanel.tsx](../../../web/src/workbench/RelayPanel.tsx)、[中转交互 §2](../../interactions/relay.md#2-电脑端登录并开启)。

## 3. 门户和电脑选择

“我的电脑”展示当前账号的电脑，状态区分在线、离线、等待电脑连接、需要重新认证和版本不兼容。只有在线且兼容的电脑可打开；撤销接入提供二次确认，并说明电脑上的 Codex 和历史继续保留。

切换路径是“返回我的电脑 → 选择目标 → 显式打开工作台”。原型在同一个预览页切换示例画面，生产继续使用门户签发的目标电脑固定授权及既有 `/g/{gatewayId}/…` 地址；不会通过改一个下拉选项复用旧电脑授权。

电脑、项目、Run、目录、正文、阅读状态和终端草稿按访问上下文区分。进入另一台电脑后，新建、文件查询和终端操作都归目标电脑；离开工作台不停止 CLI。无本机 native picker 的远程启动继续使用已有目录浏览或路径输入能力。

原型包含登录、首次改密、改密后重新登录和退出门户的状态。退出门户撤销当前网页登录及页面授权，不退出电脑账号；改密则使全部网页与电脑凭据失效。重新登录门户不会自动恢复旧页面或旧电脑凭据，仍需电脑重新认证和显式打开。

实现对应：[portal.js](../../../relay/static/portal.js)、[HistoryHome.tsx](../../../web/src/workbench/HistoryHome.tsx)、[中转交互 §3](../../interactions/relay.md#3-手机与多电脑页面)。账号管理与管理员维护沿用既有门户，本次不重新设计。

## 4. 远程工作台与配对浏览器

| 能力 | 本机 owner | RemoteOwner | PairedRun |
| --- | --- | --- | --- |
| 全局项目/历史/启动与共享设置 | 按现有 capability | 按目标电脑 capability | 不开放 |
| 指定 Run 的终端和阅读 | 可用 | 可用 | 仅被配对 Run |
| Run 下项目保存历史、文件、用量和停止 | 按既有接口和 capability | 按既有接口和 capability | 保留被配对 Run 已开放的能力，不从原型权限简表推导删除 |
| 当前 Run 的 LAN/Tailscale 接入管理 | 可用 | 可用 | 不开放 |
| 电脑公网连接器绑定/开关/退出 | 可用 | 不开放 | 不开放 |
| 本机系统目录 picker | 受平台支持限制 | 不开放，使用电脑目录浏览 | 不开放 |
| 全部电脑入口 | 门户账号登录后 | 返回原门户 | 不开放 |

PairedRun 收起新建项目/会话、全局历史和共享设置入口，只显示被配对的项目与运行；不能邀请或撤销其他浏览器。浏览器控件用于表达权限，生产鉴权仍在服务端执行。

实现对应：[本机交互 §6](../../interactions/workbench.md#6-设置lan-接入与撤销)、[AccessPanel.tsx](../../../web/src/workbench/AccessPanel.tsx)、[设备接入](../device-access.md)。

## 5. 局域网和 Tailscale 配对

设备访问默认关闭。开启后展示当前 Run 的局域网 IP 和 Tailscale 两种入口、二维码、复制操作及已配对浏览器列表。切换地址只改变当前分享的二维码，不关闭另一入口；二维码包含 Run selector 与 fragment 配对能力。

配对码在本 Run 生命周期内固定，可重复扫码，不增加五分钟倒计时或手动轮换操作。原型二维码编码合成地址与无效配对值，明确标注“示例二维码”，不提供真实接入权限。

管理列表使用“已配对浏览器”而非物理设备数量。同一手机访问 IP 和 DNS 可能形成不同授权；单条断开撤销当前浏览器，持有码的使用者仍可重新扫码。关闭设备访问撤销全部旧授权；再次开启不让旧 Cookie/输入控制权复活。关闭弹窗不关闭监听。

原型的设备访问状态按电脑及当前 Run 保存，切到其他电脑或运行时不会带入旧地址选择和配对列表。

## 6. 断线与授权失效

普通网络中断保留当前阅读画面，显示恢复提示，暂时阻止新输入与查询。未确认输入不补发，原生 CLI 继续；恢复同一 Run 后再从终端与阅读快照接续。原型演示保留同一个 xterm 容器，不把重连变成新建 CLI。

授权过期、门户退出或账号变化则清空正文、项目与历史列表、终端，以及可打开旧会话/用量详情的入口；关闭已打开的旧详情。页面显示返回门户并显式重新打开的入口，不借后续新登录恢复旧授权。PairedRun 失效后需在真实产品重新配对；原型的“回到本机示例”仅用于场景导航。

单个文件读取无权限不等于整页授权失效。连接与账号状态也不表示模型响应、工具执行、任务或 CLI 已结束。

## 7. 维护与验证

生产入口和样式映射见[布局与实现映射](workbench-ui.md)。工作台连接管理维护在 [RelayPanel.tsx](../../../web/src/workbench/RelayPanel.tsx)，Run 配对维护在 [AccessPanel.tsx](../../../web/src/workbench/AccessPanel.tsx)，账号与电脑选择维护在[门户](../../../relay/static/portal.js)。身份和授权协议继续以[本机交互](../../interactions/workbench.md)及[中转交互](../../interactions/relay.md)为准。

专项检查：

```bash
node web/e2e/product-design-probe.mjs
node scripts/dev.mjs docs
```

浏览器检查使用系统 Chrome、隔离用户目录与 loopback 合成服务，覆盖五种宽度、权限入口、目标电脑标识、终端实例保留和门户状态。绑定取消与迟到结果、撤销、授权失效及重连不重放还需由相关组件和后端回归验证，入口见[组件架构](../../architecture/workbench.md)和[中转架构](../../architecture/relay.md)。结果与截图登记在 `target/artifacts/<UUID>`；真实手机、网络与账号验收单独记录。
