# 工作台历史管理与统一 JSON 配置设计

> 2026-09-20 根据用户要求加入 R3.1。本文件定义产品与技术契约；运行实现见[验收记录](validation/native-cli-history-settings-2026-09-20.md)，任务顺序与状态只在[实施计划 R3.1](v2-implementation-plan.md#r31-history-settings)维护。关键决定见 [ADR 0048](decisions/0048-history-cleanup-and-json-settings.md)。

## 1. 用户价值、事实与范围

用户能够看到历史占用、按运行删除或批量清理，并选择是否按保留期限自动清理。工作台提供给用户的长期配置统一落在可自行指定目录中的 JSON 文件，在当前工作台点击“设置”展开可视化表单，读写同一份文件；不另建独立设置页面。

当前事实：R3 已按启动生成独立 runEpoch，数据保存在 `~/.codex-web/history/runs/<runEpoch>`，SQLite 是可重建索引；历史按 canonical cwd 的摘要隔离项目。JSON 配置、展开表单、占用/候选、后台删除任务与保留检查已接入工作树。`meta.json` 的格式 v1 严格拒绝未知字段，只有 `ended`，没有结束时间；新增独立 `lifecycle.json` 提供正常结束凭证。关闭网页不结束 Run；原生 CLI 退出后，launcher/Recorder 仍可能存活并持有运行锁。

本次项目选择：

- **默认保留全部历史，手动删除和自动清理均关闭。** 查看占用、预览候选不要求开启删除；启用“允许清理历史记录”后才允许手动确认删除。自动清理还需单独开启，单改天数不触发删除。
- 管理单位是一次工作台运行，包含该运行的日志、快照、上下文 blob 和补充元数据；不按单条聊天消息删除。结束的运行自动出现在历史中，不另建“归档”开关，也不把原生 `archived_sessions` 当工作台回收站。
- 首版只清理**当前数据目录中、当前项目的工作台历史**。同一配置目录的设置共享于多个项目，但每个运行中的工作台只执行自己项目的策略。网页必须显示该共享范围，不提供全项目一键清空。
- 原生 Codex 会话、`sessions`、`archived_sessions`、认证/模型/权限配置、旧 Observer 数据库及项目文件均不属于清理目标。网页的“工作台设置”只管理本产品的配置。
- 不实现历史恢复/回收站、云同步、全局清理守护进程、按磁盘阈值自动淘汰、原生会话导入或任意文件编辑器。长运行的部分内容清理不在本片范围。

成功标准：用户能核对占用和精确候选再删除；任何默认、无效或未确认配置均不能开启删除；活动运行始终受保护；配置/扫描/清理不进入模型代理和 PTY 转发路径。

## 2. 配置目录与文件契约

### 2.1 固定目录结构

按用户 2026-09-20 确认及 [ADR 0049](decisions/0049-workbench-user-directory.md)，macOS/Linux 默认根目录为 `$HOME/.codex-web`，Windows 约定为 `%USERPROFILE%\.codex-web`，内部共用 `config/` 与 `history/`。工作台默认位置独立于原生 `CODEX_HOME`；后者仍只用于原生 CLI 的配置、认证和会话。当前运行时依赖 Unix，Windows 路径选择逻辑通过独立测试，完整 Windows 运行尚未验收。

`codex-view --config-dir <directory>` 只用于选择配置目录。未指定时使用根目录下的 `config/`；相对路径以本次启动 cwd 解析，随后固定 canonical 路径。`--data-dir` 和 JSON `storage.dataDir` 继续覆盖历史位置。配置目录不能由其中的 JSON 再次指定，不增加项目配置叠加或新的环境变量设置。

```text
.codex-web/                        # 位于各平台的用户主目录
  config/                          # --config-dir 可单独覆盖
    config.json                    # 唯一用户配置
    config.schema.json             # 本地 JSON Schema，供编辑器使用
    config.previous.json           # 网页写入前的一份有效备份，不是配置来源
    config.lock                    # 协作写锁
  history/                         # --data-dir / storage.dataDir 可单独覆盖
    runs/<runEpoch>/               # 每次运行的分段日志、快照和上下文
      lifecycle.json               # 新运行可选的结束时间凭证，见 §5
    index.sqlite                   # 派生索引
    usage-v1/                      # 可重建的占用缓存
      lock                         # 多进程扫描互斥
      <runEpoch>.json               # 大小/测量时间/目录身份，不含正文
    cleanup/                       # 清理管理数据，不属于原生会话
      lock
      jobs/<jobId>.json             # 可恢复任务，不能放在被删除的运行中
      trash/<jobId>/<runEpoch>/     # 同文件系统内暂存，不承诺可恢复
      removed/<runEpoch>.json       # 绑定已验证任务的删除标记，用于历史 410
```

配置和数据分目录；更改配置目录不会搬迁历史，修改数据目录也不会扫描或删除之前的目录。旧 `$CODEX_HOME/workbench/config` 和 `$CODEX_HOME/workbench-data-v1` 保留原位，不自动迁移、合并或回退读取；需要继续使用时显式指定旧目录。新目录的历史列表只读取新目录，`storage.dataDir: null` 表示 `.codex-web/history`，已有绝对路径值继续生效。

工作台配置目录不得与数据目录、运行目录或原生会话目录重叠；自定义数据目录沿用 R3 独占/权限约束，不能使用原生 home、项目根或旧数据库目录。默认缺配置时以不覆盖方式创建默认文件；明确指定的目录须安全可创建，否则给出路径与原因，不静默换目录。默认根和配置目录建立为私有目录；仅默认历史需要新根时在记录线程中创建，失败按保存降级处理。正式入口支持 `--config-dir`；默认值、覆盖与展开面板的验证见实施计划中的增量记录。

初始内容见[配置示例](configuration/workbench.config.example.json)和[JSON Schema](configuration/workbench.config.schema.json)：

```json
{
  "schemaVersion": 1,
  "launch": {
    "openBrowser": true,
    "codexBin": "codex",
    "profile": null,
    "providerProfile": "unmanaged-custom"
  },
  "storage": {
    "dataDir": null
  },
  "history": {
    "cleanup": {
      "enabled": false,
      "retention": {
        "enabled": false,
        "days": 90
      }
    }
  }
}
```

`90` 是保留天数的初始表单值，两个开关关闭时没有删除效果。字段说明：

| 字段 | 规则 / 用户含义 | 生效时机 |
| --- | --- | --- |
| `schemaVersion` | 必填；当前设计值为 1，不认识的版本拒绝，不降级猜测 | 读取时 |
| `launch.openBrowser` | 是否启动时自动打开浏览器，默认 true | 下次启动 |
| `launch.codexBin` | `codex`（从 PATH 查找）或已安装 CLI 的绝对路径；不用 Shell 解释 | 下次启动 |
| `launch.profile` | 已有原生命名 profile 名，仅字母/数字/下划线/连字符，1–128 字符；null 表示沿用原生默认，不复制配置内容 | 下次启动 |
| `launch.providerProfile` | 只接受工作台已支持的适配器；当前为 `unmanaged-custom`，不扩大认证兼容范围 | 下次启动 |
| `storage.dataDir` | null 使用用户目录下 `.codex-web/history`；其他值须为绝对路径，JSON 内不展开 `~` 或环境变量 | 下次启动，不搬迁数据 |
| `history.cleanup.enabled` | 允许删除历史的总开关，默认 false；仅打开它不执行删除 | 成功保存/重载后 |
| `history.cleanup.retention.enabled` | 自动清理开关，默认 false；为 true 时总开关必须为 true，否则报字段错误 | 成功保存/重载后安排检查 |
| `history.cleanup.retention.days` | 1–3650 的整数；按可验证结束时间计算 UTC 已过天数，1 天为 24 小时 | 下次清理检查 |

`schemaVersion` 外的已知字段缺省时使用安全默认值，网页保存为完整规范化 JSON；未知字段、重复键、注释/JSONC、类型错误、无效路径与超大文件均报错，不悄悄丢弃字段。Schema 负责结构/类型，路径、重复键和执行权限由后端补充校验。未来新提供给用户的长期设置必须先定义在此契约中，并由文件与网页共用默认值、校验及说明；内部队列/安全预算不因此全部变成用户选项。

有效值优先级：**内置默认值 < config.json < 本次显式命令行参数**。现有 `--no-open`、`--codex-bin`、`--profile`、`--provider-profile`、`--data-dir` 继续作为本次覆盖，不反写文件。`--resume`、配对入口文件及 `open` 动作属于一次性调用，不保存为自动执行偏好。认证 secret、任意 CLI 参数/命令、原生模型和 sandbox 设置不进入此 JSON。

### 2.2 读取、保存与并发编辑

- 配置目录/备份/临时文件使用 0700/0600，校验当前用户、普通文件及固定目录描述符；拒绝 symlink、硬链接、设备/FIFO。读取和 HTTP 请求体上限各 64 KiB；Web API 不接受任意配置文件路径。
- 新启动遇到无效配置时，在 spawn CLI 前给出文件位置和字段错误；不覆盖原文件。已运行服务遇到损坏、缺失或权限异常时继续当前 CLI 和阅读，但暂停所有尚未执行的历史删除，设置展开面板显示错误。不得使用“上次开启删除”的配置继续清理。
- 运行期间以文件通知为重读提示，辅以后台周期检查；每个删除单位执行前再校验磁盘配置。有效外部编辑与网页保存具有相同含义，不能只写浏览器 localStorage。手动编辑开启保留期限后，也会安排当前项目的首次检查。
- GET 返回磁盘内容修订号、规范化保存值、当前有效值、CLI 覆盖来源、配置/当前数据路径、待下次启动字段及错误。修订号基于读取字节摘要，不用 mtime；内容未变可保留同一修订号，不往用户配置中插入运行元数据。
- 网页携带 `If-Match` 修订号，后端取固定 `config.lock`，重读并校验，再写同目录临时文件、fsync、原子替换、同步父目录。成功后重新读取验证才能显示“已保存”；先安全保留一份有效旧配置，备份失败则不覆盖原文件。缺前置条件返回 428，冲突返回 412，字段错误返回 422，I/O 失败不报保存成功。
- 同一配置目录的多个工作台通过同一锁协调保存。外部编辑器不遵守该锁，摘要复查能发现已发生的变化，但不能承诺对任意外部写入有完美 CAS；返回最终读取的修订号，文件变化时提示重载，保留有效旧稿便于恢复。网页不自动覆盖较新的外部编辑。
- 启动项和数据路径保存后显示“下次启动生效”；当前服务仍绑定启动时数据根与项目。历史策略针对这个有效数据根生效，不跟随未生效的新路径切换。各进程独立重载共享文件，不自动重启 CLI。

## 3. 历史占用与展示

历史列表每行显示占用和运行状态，无法删除时说明原因。顶部压缩为一行“当前项目：N 次运行 · 历史约 X MiB”，测量时间、活动运行与共享数据放入默认折叠的“占用详情”；待删除暂存非零或未知、统计不完整与策略异常仍直接可见，避免把已移出列表的数据当作已释放。未知占用显示“统计中 / 部分统计 / 无法读取”，不能用 0 代替。列表“刷新列表”同时更新占用，详情保留“重新统计”。

占用定义为运行目录内普通文件的逻辑字节数，包含日志、快照、blob 和元数据；不解析正文、不跟随链接，硬链接/特殊文件报告异常。记录测量时间与扫描覆盖；活动运行可能继续增长。按文件长度估算不等于 APFS 实际释放空间；确认框用“预计移除的文件大小”，完成后重算占用，不承诺磁盘可用空间精确增加。共享索引/任务元数据如显示大小则单列“共享管理数据”，不重复摊到每个项目，也不展示其他项目名称或正文。

独立后台扫描器、可随服务关闭停止的任务和缓存提供占用快照；扫描每轮最多处理 128 项，并在 20ms 边界让出工作线程，系统 I/O 本身仍可能延迟。大小页保存在匿名临时文件，避免将全库条目常驻内存；每页 20 项，游标绑定本轮扫描，逐运行缓存可全部重建。HTTP handler 不执行目录遍历，管理查询最多等待 3 秒；模型代理、PTY、Recorder 不等待扫描。单个数据根并发扫描数为 1，每轮按目录/文件数量和时间预算分段，启动/打开历史/手动刷新触发，不按每帧 token 重扫。面板可见时每 5 秒读取缓存，统计中每秒读取；收起停止轮询。扫描缓存可丢弃重建，不能充当删除授权。已用 10,011 个目录验证预算耗尽后可继续扫描，不将 10,000 当作保留数量。

## 4. 按运行删除与批量清理

2026-09-21 按用户反馈调整为日常列表操作：默认直接阅读记录，已结束且未被保护的行提供“删除”；点击“批量删除”后才展示勾选框、“全选已加载记录”和“删除所选（N）”，“退出选择”清空选择并恢复阅读。当前运行、仍活动或已确认无法安全删除的行不可选择。每批最多 100 条，加载更多后全选只包含已展示且可选的明确 UUID，不扩展到未加载的全部历史。

```mermaid
flowchart LR
    A["占用与明确候选"] --> B["预览：冻结 UUID / 状态 / 大小"]
    B --> C["用户确认或已启用保留策略"]
    C --> D["后台重验配置、身份与运行锁"]
    D --> E["持久化删除任务意图"]
    E --> F["原子移入本数据根暂存目录"]
    F --> G["后台删除 / 故障后继续"]
    G --> H["逐项结果与占用刷新"]
```

手动流程：单条“删除”和“删除所选”打开同一原生确认对话框，后台继续使用预览冻结候选。框中展示可删除条数、日期、大小和保留原因；预览有效期 5 分钟，绑定当前项目、数据根身份和配置修订。取消或 Escape 不创建删除任务；默认焦点位于取消。开启总开关后，用户点击“永久删除 N 条记录”完成一次明确确认；说明无法恢复、保留原生 Codex 会话和项目文件。删除未开启时说明“历史删除尚未开启”，按钮直接展开已有设置面板；保存后需回到列表重新确认，不自动接着删除。候选冻结后新增的运行不自动加入。配置、候选身份或提交元数据变化使预览失效，应重新预览，不默默扩大范围。

执行条件与恢复约束：

1. 服务端仅接受 UUID/服务器生成的 previewId/jobId，路径均在已绑定的数据根内生成。校验目录/文件所有权、类型、设备/inode、元数据中的 runEpoch/workspaceId，拒绝跨项目、跨文件系统、符号链接、路径替换和未知存储版本。锁丢失或无法校验的记录只报告原因，不能直接递归删除。
2. 当前 Run 无条件受保护；其他 Run 必须能非阻塞取得其 `lock` 的独占 flock，并保持至移入暂存及删除结束。CLI 退出、网页关闭、PID 不存在或“很久无输出”均不能替代运行锁。确认无活动 writer 的 `unclean` 记录允许手动清理，并在预览中突出异常结束/未知尾部；损坏到无法确认身份的目录不提供删除入口。
3. 预览不是持续持锁。真正执行前重验有效配置、预览、目录与提交摘要；配置关闭、失效或目标变活动时取消/跳过尚未处理项。每个数据根只有一个清理任务执行者，使用独立清理锁防止多个 launcher 并发删除同一目录，不占用 Recorder 的全局锁。
4. 先持久化任务意图和候选身份，再在同一文件系统内将整次运行原子 rename 到 `cleanup/trash/<jobId>/<runEpoch>`，同步相关父目录，再执行不跟随链接的后台删除。日志、blob、快照与 lifecycle 一并处理；不能先删日志再留下看似完整的历史条目。不能用递归删除用户传入路径或仅删除索引替代该流程。
5. 移入暂存后即从历史目录移除，但只有内容实际删除并同步后才计为完成；失败标“待清理，仍占用 X”，不假报已释放。任务状态区分 planned/quarantined/deleting/deleted/skipped/failed/cancelled，保留每项原因；没有可恢复承诺。读取中的记录若被其他页面删除，通知列表刷新并显示“此历史已删除”，清除其正文/详情缓存，保留当前 CLI 和当前用量。
6. 任务意图、rename 和逐项完成之间每个崩溃点都可恢复。重启只处理可验证的本项目任务：源/暂存目录身份匹配才继续，双份/身份不符则停止并诊断，不能扫描未知临时目录后全删。恢复也要求当前总开关开启；自动任务额外要求保留策略仍开启且目标仍到期。配置关闭后保留待清理占用，不自动续删。
7. 网页不再默认展示“清理任务”与单独“刷新任务”按钮。当前删除的进度、成功/保留/失败直接显示在确认框；关闭后仍继续，列表底部“删除操作记录”按需查询历史操作，异常和仍占用空间不能只用一个完成提示代替。任务为有界后台工作，可在两个运行之间取消；已移入暂存的单个运行作为不可逆删除单位完成，不假装撤销，也不强行打断已提交的文件系统调用。页面关闭不取消已确认任务。失去确认响应时按原 operationId 查任务，不用新 ID 重发删除。只有全部移除的任务可压缩成无正文的简要结果，待处理任务不得因结果数量上限被丢弃。
8. 完成后使占用缓存、历史集合游标及派生索引失效；其他项目资料不受影响。主动删除属于管理结果，不产生虚假的观察缺口，不改变当前 Run 的 Token 累计或保存水位。操作结果只保留 UUID、时间、大小和原因码，不复制用户正文/工具输出。

## 5. 可选保留期限与旧记录兼容

只有两个开关都开启时执行自动清理，候选限定为**非活动、正常结束且有有效结束时间凭证**的当前项目运行。启动及配置修改后安排首次后台检查，之后本工作台存活期间每小时检查一次；每轮最多 100 项，后续轮次继续，达到预算标明候选未遍历完，不编造剩余数量。策略每秒重读，删除单位开始前再读；预览/任务创建失败显示原因并在 60 秒后重试，缓存满不忙循环。服务未运行时不清理，没有新增常驻系统任务。设置展开面板说明保存开启策略后，已有到期记录也进入检查；自动任务复用相同的预览、保护、删除和结果引擎，无逐项弹窗。

期限基于 `nowUtc - endedAt >= days × 24h`，到期边界含等号。不使用开始时间、文件 mtime、最近阅读时间或模型 response 完成时间替代运行结束时间。未来时间、结束早于开始均跳过并诊断；本次进程内墙上时钟与单调时钟变化差超过 5 分钟时暂停自动清理，核对时间后重启工作台才恢复。时间仅作保留策略依据，不用作身份/去重键。

为兼容严格的 `meta.json` v1，新增独立小文件 `lifecycle.json`，不向现有 meta 强塞字段：

```json
{
  "schemaVersion": 1,
  "runEpoch": "00000000-0000-4000-8000-000000000001",
  "workspaceId": "<canonical-cwd-blake3>",
  "endedAt": "2026-09-20T12:00:00Z",
  "finalMetaDigest": "<blake3-of-committed-meta-bytes>",
  "savedRecordSeq": 42
}
```

该示例为合成身份/摘要占位。Recorder 在最终 `ended=true` 的 meta 已同步、仍持有运行锁且退出许可有效时，记录结束时间并原子写入/同步该文件；仍受原退出等待预算约束。凭证最大 4 KiB；读者验证格式版本、身份、最终 meta 字节摘要、序号和日期。凭证失败不回退已保存水位、不阻塞 CLI，只让该运行不具备自动清理资格。

旧记录不补造结束时间，也不自动迁移 meta；缺凭证、异常退出、损坏或未知版本均跳过自动清理并说明原因，可验证身份且已停止的旧记录仍支持手动删除。旧版阅读器忽略该额外文件的兼容性须用 fixture 验证。此设计不修改原生 rollout、旧 schema 20 或 `/v1`。

## 6. 网页设置与管理 API

### 6.1 简单表单与交互原型

按用户明确要求，配置采用**现有工作台内点击展开、用完收起的轻量面板**。顶栏保留一个“设置”按钮，点击后在阅读区域内展开配置浮层，沿用用量概览的展开方式和现有样式。中央对话/历史仍在原位置，右侧终端持续可见、可用；不另建设置页面、导航项、独立前端路由或浏览器标签页，不将中央阅读切换成设置视图。第一版不做 JSON 文本编辑器。

面板默认收起；再次点击按钮、点击“收起”、点击面板外部或在面板内按 Escape 可收起。按钮使用 `aria-expanded` 表达状态；由按钮/面板内 Escape 收起后焦点回到入口，点击外部时尊重所点目标的焦点，不拦截原生终端的 Escape。面板限制在阅读区域与视口内，字段较多时内部滚动；窄屏仍在当前工作台展开，不变为独立全屏设置页。

根据 2026-09-20 试用反馈，字段按用户任务排序，以中文说明用途、影响和生效时间：首先展示历史清理与保留天数，其次为已有历史/日志的位置及占用，最后为启动偏好。Codex 程序位置、已命名的启动配置及更改历史保存位置收进默认折叠的“高级启动设置”。首版接入适配器只有一个支持值，不提供无意义的下拉选择；保存仍保留完整 JSON 中的该字段。配置文件路径不在日常面板展示，只有配置损坏、需要本地修复时显示。

### 6.2 管理接口契约

均位于 `/workbench/v1`；下列 `/settings` 是展开面板使用的数据 API，不是独立网页路由。沿用本 Run 的配对身份、Host 与严格同源保护；所有写操作要求 Origin、JSON Content-Type 和 currentRunEpoch，不能继承只读 GET 允许省略 Origin 的行为，也不受终端输入权开关控制。端口复用后的旧页面返回 `stale_run`；没有通用文件写入、Shell、CLI 配置透传或旧 `/v1` mutation。

| 接口 | 关键契约 |
| --- | --- |
| `GET /settings` | 返回 schemaVersion、revision（ETag）、saved/effective、字段来源、configPath、effectiveDataDir、restartRequired、errors；配置损坏仍能看错误，第一版通过本地文件修复，不盲目覆盖 |
| `PUT /settings` | `{currentRunEpoch, config}` + `If-Match`；仅保存受支持字段，不接受路径参数。回传保存/有效值和新 revision；不启动进程、不搬迁数据 |
| `GET /history/usage?cursor=<opaque>` | 当前项目按运行大小、已扫描/总量覆盖、活动/待清理/共享管理数据、测量时间、下一页；扫描快照游标过期返回 409 |
| `GET /history/{runEpoch}/status` | 后台只核对元数据/身份，不重放正文；当前页面每 3 秒核对选中的历史，404/410 时清除阅读与调用详情 |
| `POST /history/usage/refresh` | `{currentRunEpoch}`；安排去重的后台扫描，返回 202，不等待目录遍历 |
| `POST /history/cleanup/preview` | `{currentRunEpoch, runEpochs}` 或 `{currentRunEpoch, mode:"retention", days}`；两种模式互斥。返回 202 与 previewId，最多 100 项；草稿天数仅用于只读预览 |
| `GET /history/cleanup/previews/{previewId}` | 排队/完成状态、绑定作用域/配置修订、有效期、冻结候选与逐项理由/大小；未知或跨项目为 404。纯草稿策略预览不能用于执行 |
| `POST /history/cleanup/jobs` | `{currentRunEpoch, previewId, configRevision, operationId}`；人工确认后创建任务，202 返回 jobId；同 operationId 同内容返回同任务，不同内容返回 409 |
| `GET /history/cleanup/jobs?cursor=<opaque>` / `GET /history/cleanup/jobs/{jobId}` | 当前项目任务分页/逐项结果，包含后台保留任务及失败/待清理占用；无正文。页面打开或任务运行期间读取，完成即停轮询 |
| `POST /history/cleanup/jobs/{jobId}/cancel` | `{currentRunEpoch}`；取消尚未执行的运行，返回已完成/不可撤销/已取消项，不恢复历史 |

删除未开启返回 403 `cleanup_disabled`；预览过期、配置/身份变化返回 409；非法输入 400/422，超过预算 413，繁忙/磁盘不可用 503；无配对 401，跨项目/未知目标 404，不泄露其他项目。后台任务使用相同的结构化原因码，错误携带 source、currentRunEpoch、目标 runEpoch/jobId 和阶段，不记录 payload。已知由清理任务移出的历史读取返回 410 `history_deleted`，不可验证缺失维持 404；客户端必须处理两者和历史列表游标 409。

管理接口成功返回 `{currentRunEpoch, result}`；设置接口为 `{currentRunEpoch, settings}`。任务的 `jobId` 与客户端生成的 `operationId` 相同，用于确认响应丢失后的只读核对。预览缓存最多 16 份、就绪后有效 5 分钟；管理队列最多 8 项，超时/满队列返回繁忙，不把工作借到网络或 PTY 线程。任务列表每页最多 20 项，游标绑定任务目录修订，读页前后均复核变化；任务结果只在展开时按需读取，完成后停止轮询。

`usage.result.retention` 提供 `enabled/days/state/lastCheckAt/nextCheckAt/lastJobId/lastError/scanComplete/skippedCounts`。`disabled/config_unavailable/scheduled/checking/waiting/check_failed/clock_changed` 分别表达关闭、配置失效、待检查、检查中、等待下轮、检查失败、时钟暂停；已创建清理任务的最终结果仍以该任务逐项状态为准，等待下轮不代表删除成功。自动检查与可恢复任务失败均按 60 秒退避，不自动重发网页确认。

## 7. 验证、限制与后续落点

实现前以临时 CODEX_HOME/数据目录建立旧 v1、新 lifecycle、活动锁、损坏和跨项目 fixture，不接触用户真实历史。最低验收：

- 配置：默认文件与 Schema 一致；默认无删除；覆盖优先级、未知版本/字段、重复键、损坏、原子写入/备份失败、外部编辑和多进程冲突；下次启动字段不会改变当前绑定路径/CLI。
- 占用：空库、增长中、共享管理数据、待清理目录、分页/部分扫描、不可读与链接；不把未知显示为 0，不同步扫描转发路径。
- 删除：关闭开关直接 API 请求被拒；当前/其他活动运行、跨项目、路径替换、旧预览/旧 epoch、重复确认、读删并发、异常结束手动清理、批次上限及部分失败；每个持久化/rename/删除崩溃点恢复不扩大范围。
- 保留：关闭/开启、1 天和精确边界、未来日期、无结束凭证、摘要不符、异常退出、策略中途关闭、服务重启及多个 launcher；默认、未知与损坏路径不能造成删除。
- UI/隔离：点击展开/收起、草稿保留、保存/取消/恢复/冲突、预览与结果、键盘和 1024/736/320px；无独立设置路由、URL/中央阅读选择/滚动保持，网页与文件往返同值。复用本机 Chrome，确认右侧仍为同一 CLI，面板 Escape 不拦截终端按键。慢扫描、慢删除、磁盘满与写失败不阻塞 PTY/模型，原生历史/旧数据库逐文件未改动。

保守自动清理会保留部分旧记录；应显示跳过原因并让用户选择手动处理。首次大库统计可能分多轮，不能承诺即时精确容量。原子替换不能防止不遵守锁的外部编辑器在最后间隙写入；保留一份旧稿、修订冲突提示与失败关闭删除共同约束此风险。API、生命周期旁路文件和配置格式的实现证据归 R3.1，不用本文或 JSON 样例充当运行验收。
